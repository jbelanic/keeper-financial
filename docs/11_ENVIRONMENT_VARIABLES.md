# Environment Variable Reference

`.env.example` is the executable reference for the live local Docker stack. Copy it to the ignored `.env` and replace every `change-me` value. Values prefixed `NEXT_PUBLIC_` are browser-visible and must never contain secrets. Compose overrides container-only routes so internal traffic always uses service DNS.

| Group              | Variables                                                                                                                                                                                                 | Rule                                                                                                                                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mode               | `APP_ENV`, `DEBUG`, `DEV_AUTH_ENABLED`, `REQUIRE_ADMIN_MFA`                                                                                                                                               | Live Compose uses `production`, disables debug/dev headers, and requires admin MFA. `local` is limited to isolated development/tests.                                                                                                                                                                                     |
| Origins            | `WEB_ORIGIN`, `CORS_ORIGINS`                                                                                                                                                                              | Live traffic is loopback-only HTTP; wildcards fail validation.                                                                                                                                                                                                                                                            |
| PostgreSQL         | `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DATABASE_URL`                                                                                                                                       | Compose injects `postgresql+psycopg://…@db:5432/…`; `localhost` is invalid inside the API container. Passwords used in the URL must be URL-safe or percent-encoded.                                                                                                                                                       |
| Supabase Auth      | `SUPABASE_ISSUER`, `SUPABASE_AUDIENCE`, `SUPABASE_JWKS_URL`, `SUPABASE_JWT_ALGORITHMS`                                                                                                                    | Exactly two shapes are supported (decision 46): the local CLI/Auth endpoint for dev/test (issuer loopback `:54321`; Compose routes JWKS/user through `host.docker.internal`), or an exact hosted HTTPS `.supabase.co` endpoint whose host matches `NEXT_PUBLIC_SUPABASE_URL`. Anything else fails closed in production. ES256 only.                                                                                                                                                          |
| Web identity       | `SUPABASE_INTERNAL_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`                                                                                                                      | Dev/test uses the Compose-injected `http://host.docker.internal:54321`; production uses the owner-hosted project base URL for both `SUPABASE_INTERNAL_URL` and `NEXT_PUBLIC_SUPABASE_URL` (decision 46). Only the browser-safe anon key may reach `NEXT_PUBLIC_*`. Identity plumbing is not application authorization.                                                                                                                                                   |
| MinIO              | `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_BUCKET`                                                                                                                                                  | Local-only credentials live in ignored `.env`. `minio-init` creates the private bucket idempotently and disables anonymous access; the MinIO server receives the exact loopback origin through `MINIO_API_CORS_ALLOW_ORIGIN`. `make api-dev` safely maps these values into the host-run S3 adapter without printing them. |
| S3 adapter         | `STORAGE_BACKEND`, `S3_ENDPOINT_URL`, `S3_PUBLIC_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`, `S3_REGION`, `SIGNED_URL_TTL_SECONDS`                                            | Compose uses internal `http://minio:9000`; the host-run launcher overrides the internal endpoint to `http://127.0.0.1:9000` and maps the same ignored MinIO credentials/bucket. Public access remains loopback and path-style requests are forced. No R2 settings are supported.                                          |
| Object policy      | `PUBLIC_OBJECT_URLS_ENABLED`, `MAX_DOCUMENT_BYTES`, `ALLOWED_DOCUMENT_MIME_TYPES`                                                                                                                         | Public object URLs are prohibited. Candidate files retain the PDF/DOC/DOCX allow-list and 10 MiB cap.                                                                                                                                                                                                                     |
| Agent photos       | `PUBLIC_SITE_BASE_URL`, `AGENT_PHOTO_MAX_BYTES`                                                                                                                                                           | Origin used only to compose the stable URL of an uploaded agent photo (decision 56). Must be an exact HTTPS origin with no path/credentials/query/fragment and must be `https://keeperfinancial.ca` in the live tier; **outside production a loopback `http` origin with an explicit port is also accepted** (`http://127.0.0.1:8000` in the local template) so a locally uploaded photo resolves where it is served (amendment 2026-10-25). The size cap is bounded to 5 MiB. Neither value makes the bucket public: photos are served only by `GET /api/v1/agent-photos/{photo_id}`. The composed URL is persisted on the profile, so the profile payload accepts the same loopback shape (`photo_url`) and re-composes a persisted Keeper URL against the configured base on the next save; an external URL is never rewritten. |
| Malware scan       | `MALWARE_SCANNER_BACKEND`, `MALWARE_SCANNER_FAIL_CLOSED`, `CLAMAV_HOST`, `CLAMAV_PORT`, `CLAMAV_CONNECT_TIMEOUT_SECONDS`, `CLAMAV_READ_TIMEOUT_SECONDS`, `CLAMAV_MAX_CHUNKS`, `CLAMAV_MAX_RESPONSE_BYTES` | Compose uses internal `clamav:3310`; `make api-dev` overrides only the host to `127.0.0.1`. Both modes retain bounded timeouts/chunks/responses and fail closed. Port 3310 remains loopback-only on the host. `local_test` is test plumbing and is rejected in production.                                                |
| Lead abuse guard   | `LEAD_RATE_LIMIT_REQUESTS`, `LEAD_RATE_LIMIT_WINDOW_SECONDS`, `LEAD_RATE_LIMIT_TRACKED_CLIENTS`                                                                                                           | Always-on, bounded process-local limiter; forwarding headers are not trusted.                                                                                                                                                                                                                                             |
| Legacy mortgage redirect | `MORTGAGE_APPLICATION_PROVIDER`, `MORTGAGE_APPLICATION_URL`, `MORTGAGE_APPLICATION_ALLOWED_HOSTS`, `MORTGAGE_APPLICATION_AGENT_LINKS`                                                                | Current implementation compatibility only. The approved borrower phases remove this redirect rather than repurpose client-provided destinations. Do not add new values. |
| E-sign / CRM | `ESIGN_PROVIDER`, `CRM_PROVIDER`                                                                                                                                                                          | `ESIGN_PROVIDER` selects how the injected contractor agreement is captured: `disabled`/`manual` (no provider — an administrator attests the externally signed agreement on the `executed_agreements` gate) or `documenso` (provider-owned gate plus the `DOCUMENSO_*` values). `disabled` remains the safe default and onboarding completes without any provider. No CRM adapter is implemented, so `CRM_PROVIDER=enabled` does not send leads to a CRM and must not be treated as CRM integration readiness. |
| Web/API            | `API_INTERNAL_URL`, `NEXT_PUBLIC_API_BASE_URL`                                                                                                                                                            | Server traffic uses `http://api:8000`. Side-by-side/browser-tunnel validation uses `http://127.0.0.1:8000`; final public cutover uses `https://keeperfinancial.ca` so browser API requests go through host-managed Nginx instead of the visitor's localhost. Rebuild `web` after changing this value. |
| Public site        | `NEXT_PUBLIC_SITE_URL` and the remaining `NEXT_PUBLIC_*` identity/contact values                                                                                                                          | Browser-visible owner-supplied facts. The web Docker build receives them as build arguments because Next.js embeds public values at build time.                                                                                                                                                                           |

Production startup validation is intentionally topology-specific. It rejects remote database, object-storage, and web origins, and rejects any identity endpoint other than the two approved shapes (the exact local CLI endpoint, or the exact hosted `.supabase.co` host matching `NEXT_PUBLIC_SUPABASE_URL`) rather than silently accepting hosted infrastructure. No real credentials belong in the repository.

## Borrower-application configuration

Borrower Phases B through D.2 implement the secure draft, document, consent, and submission source contract. Key material itself remains in root-owned restricted secret files, never environment values or Git. `.env.example` and Compose now include the borrower feature gates, key-file mounts, document limits, and local Docker wiring required for deployment execution after the owner's 2026-07-30 deploy/release approval. Real-data submission still fails closed unless the runtime gates are deliberately enabled and the active consent-catalog row carries the server-owned `real_data_approved=true` marker for the exact approved consent version/digest.

| Group | Current names | Required boundary |
| --- | --- | --- |
| Feature/release gate | `BORROWER_APPLICATION_ENABLED`, `BORROWER_REAL_DATA_ENABLED` | Default false; every non-local environment rejects submission while the real-data gate is off. Enabling the environment gate is insufficient by itself: the newest active/effective consent-catalog row must also carry the server-owned `real_data_approved=true` marker, which may be set only after owner approval of that exact version/digest and release evidence. The migration defaults every row to false. |
| Origin | `BORROWER_APPLICATION_ORIGIN` | Exact configured origin; no wildcard/reflection. Side-by-side validation uses the local origin documented in `docs/DEPLOYMENT_SIDE_BY_SIDE.md`; final cutover uses `https://apply.keeperfinancial.ca`. |
| Capability | `BORROWER_CAPABILITY_HMAC_KEY_FILE` | Root-owned key file; capability inactivity/revocation follows the server-owned draft lifecycle. |
| Encryption | `BORROWER_ENCRYPTION_ACTIVE_KEY_ID`, `BORROWER_ENCRYPTION_KEYRING_FILE` | Versioned key IDs and a root-owned read-only keyring file; no key bytes in environment. |
| Draft retention | `BORROWER_DRAFT_INACTIVITY_DAYS` | Fixed at the approved 30 days. Reads, failures, no-op saves, and internal activity do not extend it. |
| Start abuse guard | `BORROWER_RATE_LIMIT_REQUESTS`, `BORROWER_RATE_LIMIT_WINDOW_SECONDS`, `BORROWER_RATE_LIMIT_TRACKED_CLIENTS` | Bounded process-local control that does not trust forwarding headers. Deployment-level capacity and proxy controls remain pending. |

The following settings remain reserved for later document, retention, and deployment phases and are not Phase B runtime configuration:

| Group | Reserved names | Required boundary |
| --- | --- | --- |
| Ingress trust | `TRUSTED_PROXY_NETWORKS` | Explicit approved ingress only. |
| Internal MFA policy | `REQUIRE_AGENT_MFA` | Internal borrower access remains unconditionally AAL2 in current source; any deployment setting must not weaken that rule. |
| Object storage | `BORROWER_S3_BUCKET`, `BORROWER_S3_ACCESS_KEY_ID`, `BORROWER_S3_SECRET_ACCESS_KEY` | Dedicated private bucket/least-privilege credentials; secret value remains ignored. |
| Document limits | `BORROWER_MAX_DOCUMENT_BYTES`, `BORROWER_MAX_DOCUMENT_COUNT`, `BORROWER_MAX_TOTAL_DOCUMENT_BYTES` | Implemented typed settings default to and cannot exceed the owner-approved 25 MiB, 25 current files, and 250 MiB aggregate plaintext maxima. Configuration may narrow only. PDF/DOC/DOCX/JPEG/PNG remain the fixed strict allow-list; structure agreement and fail-closed ClamAV remain mandatory. |
| Notification email | `SMTP_ENABLED`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_USE_TLS`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `LEAD_NOTIFICATION_EMAIL_ENABLED`, `LEAD_NOTIFICATION_ADMIN_EMAIL`, `LEAD_NOTIFICATION_BROKER_EMAIL`, `LEAD_NOTIFICATION_SUBJECT` | Optional non-fatal notifications. When `SMTP_ENABLED=true`, borrower assignment can email the assigned agent. When both `SMTP_ENABLED=true` and `LEAD_NOTIFICATION_EMAIL_ENABLED=true`, new public contact leads send PII-minimized notices: selected published agent when one is attributed, otherwise broker-of-record address, and a separate administrator notice when configured. Transport failure never blocks the assignment or lead submission. When false (default, including local), no mail is sent. For an authenticated relay, set `SMTP_USE_TLS=true` plus `SMTP_USERNAME`/`SMTP_PASSWORD` (login occurs over STARTTLS when both are set); leave credentials empty for the local open relay. Docker-local Supabase Mailpit exposes its HTTP capture/API surface on `host.docker.internal:54324`, and the local lead-notification path uses Mailpit's HTTP send API for that endpoint before SMTP fallback. |
| Backup retention | `BORROWER_BACKUP_RETENTION_DAYS` | Approved value is 30 days and must fail closed if changed without a later decision. Submitted retention is the server-enforced seven-year rule, not a deployment-tunable value; legal hold blocks submitted purge only. |
| Operational backup / monitoring | `BACKUP_POSTGRES_DIR`, `BACKUP_MINIO_DIR`, `BACKUP_ENCRYPTION_KEY_FILE`, `USB_MOUNT`, `ALERT_EMAIL` | Decision 49 P0. Full procedure: `docs/operations/backup-restore-runbook.md`. Scripts: `scripts/backup_all.sh` (coordinated encrypted PostgreSQL `pg_dump` + boto3 MinIO mirror), `scripts/backup_usb.sh` (verified encrypted USB off-host copy), `scripts/monitor_health.sh` (API/DB health, ClamAV availability, backup/USB freshness), `scripts/send_alert.py` (alert email via the SMTP relay), and `scripts/reconcile_restore_deletions.py` (restore-time deletion safety gate). Run backups and the monitor from cron; a failure sends an alert to `ALERT_EMAIL`. `BACKUP_ENCRYPTION_KEY_FILE` is a separate passphrase file kept outside the repo and outside the backup destination. |
